# 加密/防护游戏怎么办：识别→解密→兜底 全阶梯（无现成案例，方法论按通用对抗整理）

## 第一步：先分诊——"不能绘制"其实是四种病
读一个 pawn 的位置连拍 10 帧，按现象分：
1. **全乱码/天文数字** → 值加密（XOR/编码）
2. **链子断了**（某级指针解出的地址不在模块可读范围）→ 指针混淆
3. **数据是好的，框不跟屏幕/游戏闪退** → 环境检测（root/悬浮窗/注入被检测），不是加密
4. **有两份都像真的坐标** → 真假缓冲区（蜜罐）

## 第二步：对症解法
### 指针混淆（UE4 手游最常见，本质是引擎魔改）
- 常见模式：真实指针 = 读出的值 ^ (f(父地址,偏移))，f 候选：固定常数、父地址>>12、偏移本身、(addr+off)>>4 等
- 爆破法：写 probe 循环——对一个 pawn 沿链逐级试密钥模式，**判据=解密后 ptrSane（落在 so 可读段+8字节对齐）且 100 个 pawn 全链存活率一致**。运气密钥只能过一两个，真密钥全过
- 密钥藏身处：常就在链子附近 ±0x100 或全局计数器，找到后记录"密钥源地址"进报告持续监控（版本更新最常改密钥不改结构）

### 值加密（坐标 float 被编码）
- 静态异或：利用已知明文——z 值总是"站在地面高度带"、相邻帧位移<100、同队坐标聚集——对密文做 bit 位反推：逐字节 XOR 候选键，看哪组能让所有 pawn 的统计特征归位
- 动态密钥：每帧变 → 找全局帧计数器/时间戳低 32 位，坐标解密=值^计数器，验证同 pawn 同帧多读一致
- 半精度/缩放存储：不是加密——float32 变 float16/定点数，按结构判据重新拟合量级即可

### 真假缓冲区
- 行为验证法唯一可靠：屏幕停一个敌人 → 两份候选里"跟画面位置对上的那份"是真的；两都能对上时选连续性好的（跳变帧数少的）
- 蜜罐特征：假缓冲刷新频率异常（每帧相同/完全不动）、地址区间规整（.data 里整块预留）

### 环境检测（值没加密但游戏不让跑）
- 分级：① su/root 存在检测 → Magisk denylist/Shamiko 挂游戏进程隐藏 ② 悬浮窗枚举 → 换窗口类型/降透明度策略、用 SurfaceFlinger 层注入 ③ 输入设备枚举(看到 uinput 虚拟触摸) → 改设备名伪装常见外设 ④ 截屏回调检测 → 绘制层与系统层分离
- 铁律：先确认被检测的是哪层再动手，全量上隐身会互相干扰难归因

## 第三步：终极兜底——内存通道全封死时，改走"屏幕永远不加密"
- 路线：root 层截屏(scrcpy协议/SurfaceFlinger) → OpenCV/YOLO 实时识别人形与部位框 → 透明层照画 ESP → 自瞄改"识别框中心→触摸拖拽"
- 代价与判据：识别延迟>80ms 体验崩；远处小目标召回率<50% 等于没透视——先用 20 帧样本测检测器再决定投入
- 这就是 ai-gateway 方法论里"模式B薅网页版"的同族思路：**数据源被保护，就换一条不受保护的数据源**

## 止损线
- 指针混淆爆破 4 小时无过全链密钥 → 转值级分析；值级 4 小时统计特征无法归位 → 转 CV 兜底；CV 测召回不达标 → 这游戏不值得做，换目标
- 每一步的负结论照旧写进报告与 battle_log（加密类项目负结论最省时间）

## 专章：腾讯 ACE 系（和平精英/三角洲行动）的坐标加密——纯读外挂的真实处境与打法
### 它是什么加密
- 典型形态：RelativeLocation/指针链 **XOR 密钥表 + 每版本轮换算法**（不是固定算法，热更就改）；三角洲=UE5(FVector 变 double，一个坐标 24 字节，"3×float 量级判据"整层失配) + Chaos 物理(Embree 链没有，另挖) + 强环境检测
- 附带：ACE 检测链（root/注入/悬浮窗/输入设备全在射程内）

### 纯读架构可用的四条路（按性价比）
1. **找明文镜像（首选）**：一个坐标在游戏里从不只存一份——
   - 相机 POV(ViewLocation) 必须近明文否则渲染管线不成立 → 己方位置永远可得
   - 组件有两套骨骼缓存(ComponentSpace/BoneSpace，本项目考古亲验)，加密常只动一套；网格世界变换(C2W)与 root 位置常不同密甚至一明一暗
   - 服务器同步缓冲/物理 tick 源：写加密字段的"上游"往往留明文短暂窗口
   做法：对加密字段所在对象，把相邻/同链其他字段的读取窗口拉大(±512B)，跑"统计归位"筛(地面高度带/聚集性/帧连续性)，明文镜像自带这些特征，密文没有
2. **追写入者**：root 下硬件观察点(arm64 hw_breakpoint/perf watchpoint)监控加密字段，抓"谁在写它"→写入方调用的源结构=明文真身，直接换读源结构。这是被加密逼到墙角时最一劳永逸的招
3. **逆密钥表**：密文=明文^表项，密钥表本身每帧更新但更新源是全局计数器/随机池——找表(与 pawn 数等长/4~8字节循环/地址规整的 .data 块)+找源；注意版本轮换=每月重做，纯读者最恨的路
4. **CV 兜底（强对抗游戏的稳定路）**：反作弊管得到内存管不到屏幕。录屏→模型识别→透明层绘制/触摸拖拽自瞄。延迟和召回的取舍见上一节判据

### 诚实结论（不喂幻觉）
- 和平精英这种"算法周更+ACE在线对抗"的游戏，纯读 ESP 是**持续战**：每个版本重跑考古，个人玩家版本空窗期按周算。技术上没有"一劳永逸"，只有"哪条路重挖最便宜"——明文镜像法和观察点追写入的复用性最高，密钥表法最低
- 三角洲(UE5)先过双精度关再谈加密
- 单机/弱检测游戏(FPS2 这类)和 ACE 在线游戏的正确策略本来就是两条：前者纯读，后者要么镜像/CV，要么别碰
